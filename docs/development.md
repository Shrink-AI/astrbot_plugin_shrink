# 自主开发约定

修改前读取本文件及 `docs/architecture.md`。保留现有行为与用户改动；先查看线上版本、草稿差异和测试记录。冲突用 `refresh` 归档旧草稿后重新检出，再按需求取回修改，不整份回退线上版本。

决策层开发与合成离线评测见 [决策接口与离线评测](decision-layer.md)。新增后端实现统一输入／输出契约；不能从模型输出取得权限、身份或未召回的任务标识。

## 模块边界

- `services` 处理业务规则，不导入 AstrBot、FastAPI 或 `adapters`。
- `persistence` 保存 SQL、事务和持久化状态。事务中不能等待网络。
- `adapters` 对接宿主、模型、平台和网络；`api` 调用已装配的服务。
- 提示词放在 `shrink/prompts`，用户可编辑版本通过提示词服务管理。
- 独立插件使用能力协议，不导入其他插件或读取其私有配置；不在核心里新增特定提醒、站点或电脑 Agent 的实现。

## 对外表达和发送

新增核心通知调用 `conversation.notifications.send_once(event, key, facts, request=..., kind=...)`。

- `facts` 只传已确认的执行事实；原请求单独传入。不能把模型的“完成了”当执行证据。
- `key` 来自原消息、任务或事件的稳定标识；内部重试使用同一标识。不能每次生成随机编号规避去重。
- 统一入口负责当前人格、原会话范围、表达、发送预占、回执和聊天记录；发送结果未知不自动重发。显式补发可重新领取 failed、interrupted 及无活跃执行者的 composing 回执；sending、unknown、platform_accepted、silent 不重发。部署启动恢复只尝试一次，失败后等待下一次明确恢复，不循环重写任务状态。
- 调用工具不是通知的理由：工具调用前不发提示，子代理内部步骤不通知用户。工具前钩子只同步记录“工具已开始”，不等待、不发送，也不能用来拦截工具。
- 前台聊天请求不带宿主的 shell、Python、shell session 和 `transfer_to_*`；需要运行脚本或多步执行的工作提交为后台任务。筛选只作用于当前请求的工具集，名单在 `shrink/adapters/foreground.py`。
- 第二气泡、表情等附加发送在会话锁之外进行，平台接受后才写入聊天记录。
- 跨会话认识只通过 `RecentInteractions` 取：范围是当前发言人自己的发言和石英对他的回复，带来源与说话人；私聊只在该私聊内或本人原话点名时使用。不得另写查询绕过这个范围，也不得把“没选进上下文”或“没查到”表述成没发生。
- 改动前台钩子、停止或防抖逻辑后，除常规 pytest 外还要跑 `tests/host`（需要安装 `astrbot==4.29.4`，命令见文件头）；没装宿主时这组测试会被跳过，跳过不算通过。宿主会吞掉钩子里抛出的一切异常（包括取消），要让一轮结束只能结束事件传播。
- 聊天历史由核心写入和重建：req.conversation=None 禁止宿主同时写历史；动态检索放新消息，不拼入 system。输入先提交 input_events 和 messages，再进入防抖；task_inputs 复用该标识。压缩与撤回不得删除原文引用。
- 每个前台轮次落一条 `turn_traces` 记录（输入、会话、发言人、运行标识、后台任务、各阶段耗时和结局），`GET /api/v1/turns/latency` 给出 p50／p95／最长。新增的前台等待必须归入已有阶段或新增阶段，不能落在记录之外。
- 同一发言人的新消息会让尚未动手的旧轮在请求钩子入口退出、在回复钩子里跳过表达。停止运行中的旧轮只能走宿主的协作停止（`foreground.request_stop`），不直接取消其任务；该路径由设置 `cooperative_stop` 控制，默认关闭，真实宿主集成测试通过前不要打开。
- 普通聊天保留 `ConversationAdapter` 的最终表达链路。不得在工具钩子或子代理内直接 `event.send`、`send_message` 或发送固定占位文案。
- 独立插件使用 `message.compose` 能力生成文本，自行持久化任务和发送回执，确认平台接受后调用 `record_sent`。不得依赖核心 Python 模块。

## 任务和资料范围

停止请求先取消对应会话、创建者的任务，不得转成开发或续做任务。前台超时不取消已经提交的后台任务，也不因读过工具或历史聊天就新建任务。模糊的进度追问只查对应工作，不把历史摘要中的旧任务全部恢复。

子代理创建时写明人格、职责、输入、范围、工具和验收条件。默认继承石英人格；开发模型使用已配置的 provider。通过原生工具发现插件、MCP、知识库和沙箱能力，按任务分配。`tools=["*"]` 表示选择当前实际启用的全部可发现工具，普通分工优先明确列出所需工具。

开发需求先加载原生 `grilling` Skill。按当前可决定的分支批量询问并给推荐选项，已确认方案不重复问；明确要求直接执行时跳过访谈。子代理执行中遇到关键歧义用 `shrink_orchestrate ask_user`，问题和现场持久化，任务状态变为 `waiting_user`。父任务合并子任务问题再交由石英询问；仅原会话、原创建者可用 `resume` 和 `answer` 续做，空答复不恢复。

运行中任务的补充使用 `shrink_orchestrate append_input`（`task_id`、`text`）；入口从原事件取消息标识，仅接受原会话、原创建者，去重后立即返回接收位置。输入仓储和规则分别在 `persistence/task_inputs.py`、`services/task_inputs.py`；宿主适配在完整 runner 步骤之间交付，保存上下文及 entered／processed 位置。关闭进程按尝试及工具回执进入 queued、reconciling 或 needs_attention；原创建者 resume 恢复同一任务的新尝试；用户取消的任务不交付未消费输入。后台同构体不能调用 append_input 冒充原创建者。resume 沿用任务并发限制，并把缺少结束回执的工具记录作为结果未知交给模型先核对。任务 SQL 归 persistence/tasks.py，转换规则及启动恢复归 services/task_states.py，执行与持久重试归 services/task_execution.py；检查点按消息增量保存，运行时序列化、写入和清理在工作线程完成，不保存内联图片，完成或取消后清理。

子代理可以主动调用 `shrink_lookup` 召回记忆，继承任务的可信原会话和创建者。知识库与 Skills 按原生接口检索、读取；记忆内容仍经过既有范围、置信度和来源规则，不能通过直接读原始知识库绕过。参考资料不是新授权；经验与资料交回核心整理，不另建记忆。Skill 写可复用方法、适用条件和验证步骤，不保存私人任务参数。

## 验证和部署

按改动验证正常、失败、重复、取消和跨会话情况。语法通过、隔离测试通过、宿主加载成功、实际效果成功分别报告。测试不连接生产 QQ、不写生产数据；没有发送回执不能宣称送达。

工作台在 `check`、`test` 和 `deploy` 校验核心分层和发送入口。已有运输代码仅在函数内容不变时沿用；改动这些函数时应迁入统一入口。工作台检查器及统一通知运输实现属于维护端审查边界，不能由草稿自行放宽。此检查防止常见架构违规，不是执行不可信代码的安全沙箱。

运行相关测试后查看 `status` 和 `diff`，确认当前草稿证据有效再部署。核心重载交给独立执行器；不能继续在已经卸载的任务里写入。失败恢复备份，停止后未经新的继续指令不得重启任务。


### 执行时长与运行重载

前台回复、开发和编排任务不设整轮墙钟时限。用户仍可停止任务；单次网络请求、工具执行和隔离测试保留各自的超时，不能把请求超时说成整项任务超时。

管理员可调用 `shrink_reload(mode="hot")` 重载石英核心，`mode="cold"` 通过 AstrBot 原生接口重启整个进程（会短暂断开平台连接）。独立执行器持久记录请求，等待调用中的后台任务退出；有其他执行中的任务时拒绝。提交只代表待处理，新核心启动代次改变且健康检查通过才记成功，结果经统一表达链路回传。重载回执未知时不自动再次重启。重载不会合并或部署草稿，代码部署仍须使用工作台测试与部署流程。
