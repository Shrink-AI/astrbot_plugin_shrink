# 自主开发约定

修改前读取本文件及 `docs/architecture.md`。保留现有行为与用户改动；先查看线上版本、草稿差异和测试记录。冲突用 `refresh` 归档旧草稿后重新检出，再按需求取回修改，不整份回退线上版本。

决策层开发与合成离线评测见 [决策接口与离线评测](decision-layer.md)。新增后端实现统一输入／输出契约；不能从模型输出取得权限、身份或未召回的任务标识。

## 模块边界

- `services` 处理业务规则，不导入 AstrBot、FastAPI 或 `adapters`。
- `persistence` 保存 SQL、事务和持久化状态。事务中不能等待网络。
- 聊天、管理交互、规划、执行、后台表达、紧急表达和维护配额集中在 `services/scheduling.py`；不要在适配器里另建共享模型信号量。HTTP、外部能力入口和提示词试跑使用 interactive，spawn 的后台工作重置为 maintenance；message.compose 模型沿用 expression。前台新增等待必须计时，不能借降级扩大资料、权限或任务范围。前台遇忙的重排直接降级，历史按持久边界读取且不等待后台摘要锁，管理写遇忙明确说明尚未执行，不绕过写锁。
- `adapters` 对接宿主、模型、平台和网络；`api` 调用已装配的服务。
- 提示词放在 `shrink/prompts`，用户可编辑版本通过提示词服务管理。变量用双花括号；模板改动要用真实默认模板验证。旧覆盖项迁移保留原版本历史，目录外旧键只归档，不恢复隐式追加机制。
- 独立插件使用能力协议，不导入其他插件或读取其私有配置；不在核心里新增特定提醒、站点或电脑 Agent 的实现。

## 对外表达和发送

新增核心通知调用 `conversation.notifications.send_once(event, key, facts, request=..., kind=...)`，先进入核心持久发件箱；返回 False 也可能是排队、延后或抑制，调用方不得回退原文或另行发送。排队与选择规则在 services/notification_outbox.py、notification_selection.py，SQL 在 persistence/outbox.py，平台发送仍在原 Notifications.send_once。

- `facts` 只传已确认的执行事实；原请求单独传入。不能把模型的“完成了”当执行证据。
- `key` 来自原消息、任务或事件的稳定标识；内部重试使用同一标识。不能每次生成随机编号规避去重。
- 统一入口负责当前人格、原会话范围、表达、发送预占、回执和聊天记录；发送结果未知不自动重发。显式补发可重新领取 failed、interrupted 及无活跃执行者的 composing 回执；sending、unknown、platform_accepted、silent 不重发。部署启动恢复只尝试一次，失败后等待下一次明确恢复，不循环重写任务状态。
- 调用工具不是通知的理由：工具调用前不发提示，子代理内部步骤不通知用户。工具前钩子只同步记录“工具已开始”，不等待、不发送，也不能用来拦截工具。
- 前台聊天请求不带宿主的 shell、Python、shell session 和 `transfer_to_*`；需要运行脚本或多步执行的工作提交为后台任务。筛选只作用于当前请求的工具集，名单在 `shrink/adapters/foreground.py`。
- 第二气泡、表情等附加发送在会话锁之外进行，平台接受后才写入聊天记录。
- 跨会话认识只通过 `RecentInteractions` 取：范围是当前发言人自己的发言和石英对他的回复，带来源与说话人；私聊只在该私聊内或本人原话点名时使用。不得另写查询绕过这个范围，也不得把“没选进上下文”或“没查到”表述成没发生。
- 改动前台钩子、停止或防抖逻辑后，除常规 pytest 外还要跑 `tests/host`（需要安装 `astrbot==4.29.4`，命令见文件头）；没装宿主时这组测试会被跳过，跳过不算通过。宿主会吞掉钩子里抛出的一切异常（包括取消），要让一轮结束只能结束事件传播。
- 聊天历史由核心写入和重建：req.conversation=None 禁止宿主同时写历史；动态检索放新消息，不拼入 system。输入先提交 input_events 和 messages，再进入防抖；task_inputs 复用该标识。主历史独立使用 history_compress_tokens=128000、history_retain_ratio=0.65；context_budget 只管辅助窗口。越过估算阈值先持久化固定边界、原文引用和空摘要，前台不调模型、不等摘要锁；维护配额后台以 180 秒单次预算、共 3 次尝试补做同一检查点，最终失败不逐轮重试，重启从持久状态恢复。摘要落地可改变前缀一次，落地前后各自只追加；新检查点预留 min(4000, 阈值×0.2)、至少 1 估算 token，已有预留值沿用。摘要正文上限扣除引用说明后经 max_tokens 传入模板，超长输出截取兜底。摘要输入含 system 的上限按检查点 B=window_budget、S=summary_tokens 换算为 max(32000, B+S+max(4000, ceil(B/10)))，默认 144800、最大窗口 2204000 估算 token；不读取后来修改的设置，正常覆盖完整纳入，超限取最近完整块并说明省略；失败范围在容量内继续纳入，撤回后重建也受限，所有省略原文仍可引用。前台单条超大消息保持完整，旧摘要导入不能遮掉阈值内原文，压缩与撤回不得删除原文引用。
- 每个前台轮次落一条 `turn_traces` 记录（输入、会话、发言人、运行标识、后台任务、各阶段耗时和结局），`GET /api/v1/turns/latency` 给出 p50／p95／最长。新增的前台等待必须归入已有阶段或新增阶段，不能落在记录之外。
- 同一发言人的新消息会让尚未动手的旧轮在请求钩子入口退出、在回复钩子里跳过表达。停止运行中的旧轮只能走宿主的协作停止（`foreground.request_stop`），不直接取消其任务；该路径由设置 `cooperative_stop` 控制，默认关闭，真实宿主集成测试通过前不要打开。
- 普通聊天保留 `ConversationAdapter` 的最终检查及发送链路，主人格本轮答复就是最终表达，用过工具也不再必经第二次模型改写。`ExpressionService.finish` 始终清理推理／元叙述；只有原始资料／提示词外露或无证据执行声明才恢复一次，再失败时非必要内容静默，必要结果只用已知状态生成简短说明，不回退不安全原文。普通形态超过 `max(limit*2, 60)` 或近期重复走原专用 rewrite（30 秒），失败保留安全原文，再按整句截取；无法整句截取时取前 60 字符内最后一个分句边界（，、；：及空白），无边界才硬截。tool_result／detail 不检查重复，超过 8000 字符确定性截取；不得因长度或重复静默。无证据完成声明的专用沟通要求通过 execution_status 的 instruction 传入，不扩充公共 outbound.contract。不得在工具钩子或子代理内直接 `event.send`、`send_message` 或发送固定占位文案。
- 前台外露比对只取执行与工具输出。用户明确要代码／配置／日志／工具原文或 form=detail 时，允许必要 JSON 片段和工具长引用，代码块内跳过结构／提示词片段检查；裸 JSON、系统提示词原行、聊天模板标记仍拦截。未明确要求及后台 safe_expression 均保持严格，不能把前台参数传给后台放宽。
- 回复形态继续由原 wants_detail 正则决定；外露检查独立用 allows_tool_quotes（其超集）判断明确索取代码／日志／配置等请求，不能用放行范围扩大闲聊长回复触发条件。
- 工具 JSON 供主人格理解，`execution.version=1` 仅提供状态证据；不因调用了工具或读过旧任务就声称完成。前台与发件箱统一使用 `Outbound.persona`、`turn_context` 和 `outbound.contract`，通知只重建可信原会话的资料。表达约定放进主模型固定 system，开头限定工具／任务／执行结果适用，闲聊按人格与本轮要求来。升级将旧 compose 全文规则拆为 contract 覆盖，compose 恢复资料壳，原文保留历史；人格覆盖逐字保留。2026-11-15 已决定受理一句极简短句，不复述参数／路径／模型／步骤，不介绍同构体或派工过程，不加等待／回报尾巴，重复受理安静；提到子代理仍叫“我的同构体”。默认契约与线上人格覆盖的受理口径一致，无须编辑人格覆盖，结果／失败／未知／待决定事项照常保留；不增加其他聊天风格规则。
- `turn_traces.expression_model_calls` 是本轮实际额外表达调用次数，正常为 0、恢复至多 1；主模型调用数另存。`GET /api/v1/turns/latency` 返回调用总数、最大值、零调用及已观测轮数，新增列前的未知观测为 NULL，不解释成零。聊天配额排队计入 `chat_queue`，检索、embedding、Skills 和历史准备等待计入 context。
- 保留发件箱的收件箱／防抖／活跃前台优先和表达后 preflight。普通表达等到配额后必须再检查新输入；必要结果达到 notification_max_delay（默认 60 秒）后不再因前台活跃或待处理输入让路，但事实／所有权／去重仍复核。进展不适用上限；停止、授权撤销、需要决定的阻碍和提问使用原紧急类别，不能排在普通表达后。不要改动统一运输函数来实现调度。
- 独立插件优先使用 `message.notify submit/status/retry/cancel`，提交稳定事件标识、消息类型、事实和可信原会话；提交后不得自行发送。retry 仅重新排队明确未发出的失败或没有活跃执行者的中断项，重复 submit 不补发；cancel 只撤回尚无表达回执的 pending／merging，返回明确 cancelled 终态。拒绝操作返回当前状态及 applied=False，不能换标识规避。`message.compose`／`record_sent` 保留给外部插件仍持有发送权的兼容事件。每会话、创建者、消息类型及稳定事件分别固定发送所有者，冲突静默或拒绝，不自动切换。未迁移插件仍负责自身发送幂等；契约见 plugin-protocol.md。不得依赖核心 Python 模块。
- 插件可提交最长 1000 字符的可读 fallback_text，接收时只豁免 facts 中 80 字以上字符串的原样包含规则；裸 JSON、提示词结构、堆栈、人格原行及长度仍检查。不安全只拒收文本，通知照常接收。必要结果表达失败或表达因原样引用长事实被拦后，可使用已校验兜底；未提供时保持原行为，发送前继续 preflight。不能直接从 facts、工具 JSON、事件 body、异常全文或提示词生成兜底。新增 SQL 和迁移放 persistence，规则放 services。

## 任务和资料范围

停止请求先取消对应会话、创建者的任务，不得转成开发或续做任务。前台超时不取消已经提交的后台任务，也不因读过工具或历史聊天就新建任务。模糊的进度追问只查对应工作，不把历史摘要中的旧任务全部恢复。

子代理创建时写明人格、职责、输入、范围、工具和验收条件。默认继承石英人格；开发模型使用已配置的 provider。通过原生工具发现插件、MCP、知识库和沙箱能力，按任务分配。`tools=["*"]` 表示选择当前实际启用的全部可发现工具，普通分工优先明确列出所需工具。

开发需求先加载原生 `grilling` Skill。按当前可决定的分支批量询问并给推荐选项，已确认方案不重复问；明确要求直接执行时跳过访谈。子代理执行中遇到关键歧义用 `shrink_orchestrate ask_user`，问题和现场持久化，任务状态变为 `waiting_user`。父任务合并子任务问题再交由石英询问；仅原会话、原创建者可用 `resume` 和 `answer` 续做，空答复不恢复。

运行中任务的补充使用 `shrink_orchestrate append_input`（`task_id`、`text`）；入口从原事件取消息标识，仅接受原会话、原创建者，去重后立即返回接收位置。输入仓储和规则分别在 `persistence/task_inputs.py`、`services/task_inputs.py`；宿主适配在完整 runner 步骤之间交付，保存上下文及 entered／processed 位置。关闭进程按尝试及工具回执进入 queued、reconciling 或 needs_attention；原创建者 resume 恢复同一任务的新尝试；用户取消的任务不交付未消费输入。后台同构体不能调用 append_input 冒充原创建者。resume 沿用任务并发限制，并把缺少结束回执的工具记录作为结果未知交给模型先核对。任务 SQL 归 persistence/tasks.py，转换规则及启动恢复归 services/task_states.py，执行与持久重试归 services/task_execution.py；检查点按消息增量保存，运行时序列化、写入和清理在工作线程完成，不保存内联图片，完成或取消后清理。

子代理可以主动调用 `shrink_lookup` 召回记忆，继承任务的可信原会话和创建者。知识库与 Skills 按原生接口检索、读取；记忆内容仍经过既有范围、置信度和来源规则，不能通过直接读原始知识库绕过。参考资料不是新授权；经验与资料交回核心整理，不另建记忆。Skill 写可复用方法、适用条件和验证步骤，不保存私人任务参数。

向量全索引扫描、夜间相似度计算及附件解码／写入使用调度服务的计算线程；聊天与后台线程分开。线程只处理快照和文件，不共享主线程 SQLite 连接；计算后写回前重新核对版本。SQLite 保留默认写锁等待，主连接仍可能同步等锁最长 5 秒；执行上下文、部署与重载的独立连接也会写同一库。该阻塞尚未解决，需要线上测量后再决定方案；磁盘停顿和大库扫描同样不能宣称已解决，完整资源盘点见 architecture.md。

前台空闲检索／重排分别由 Settings 的 `foreground_retrieval_timeout`／`foreground_rerank_timeout` 控制，默认 10／20 秒；`foreground_grilling_timeout` 默认 0，表示不额外加总时限，原有两个 HTTP 请求各 45 秒不变。参数线上测量后再调，不能未经测量悄悄降低召回预算。启动整库升级映射旧 settings 并补齐默认值；被删除或未知的键和值先归档到 upgrade_archive，再从当前设置移除，不放宽 Settings 的额外字段校验。后台占用共享锁时仍立即降级。

## 验证和部署

按改动验证正常、失败、重复、取消和跨会话情况。语法通过、隔离测试通过、宿主加载成功、实际效果成功分别报告。测试不连接生产 QQ、不写生产数据；没有发送回执不能宣称送达。

升级入口为 `tools/upgrade_preflight.py DATABASE --report REPORT.json`，不依赖 AstrBot、网络或模型，操作前须保证目标库无其他写入者。实现先做 SQLite 一致备份，修复损坏提示词表、归档旧设置／前缀、迁移结构和状态，再核对原记录身份与内容摘要及实际查询路径；失败恢复本次备份。生产快照保持只读，测试和预检均用副本；私人原文不得进入源码、夹具、文档或报告。明确机器人草稿尾段只在首次升级修正，不建审核积压或运行期旧数据过滤。完成升级的启动不做业务整表扫描、全库完整性检查或整库备份，未知设置仅归档清理，新增默认值由 StateRepository 补齐。具体上线、健康检查与回滚见 [上线步骤](upgrade.md)。

阶段 3 收尾验证在 `tests/host/test_stage3_questions.py`（真实 runner 的父子问题回传／原任务答复续做）与 `tests/test_stage3_recovery.py`（依赖及重开、真实子进程 kill、重复答复及事件重放）。子进程测试在一次性数据库中途写入，父进程在文件屏障到达后 kill，不用正常 close 代替强杀；检查未消费输入恢复一次、已接受发送不重放、sending→unknown、未知工具写入进入 reconciling。独立提醒联调在 `tests/test_reminder_plugin_integration.py`，目录可由 SHRINK_REMINDER_PLUGIN_ROOT 指定，缺失明确跳过；脚本模型和假平台通过不等于真实模型／QQ 验收。提醒插件无 retry／cancel 的旧核心按不支持处理，保留 status 等待核对，不改变发送所有者。

pytest 通过 `tests.tempfiles` 在全局 stdout／stderr 捕获启动前检查临时目录；系统临时目录不可写而回退到仓库根目录时，改用 pytest 临时目录。正常可用的系统临时目录不变，回归覆盖启动期及测试执行期的实际文件位置。

工作台在 `check`、`test` 和 `deploy` 校验核心分层和发送入口。已有运输代码仅在函数内容不变时沿用；改动这些函数时应迁入统一入口。工作台检查器及统一通知运输实现属于维护端审查边界，不能由草稿自行放宽。此检查防止常见架构违规，不是执行不可信代码的安全沙箱。

运行相关测试后查看 `status` 和 `diff`，确认当前草稿证据有效再部署。核心重载交给独立执行器；不能继续在已经卸载的任务里写入。失败恢复备份，停止后未经新的继续指令不得重启任务。


### 执行时长与运行重载

前台回复、开发和编排任务不设整轮墙钟时限。用户仍可停止任务；单次网络请求、工具执行和隔离测试保留各自的超时，不能把请求超时说成整项任务超时。

管理员可调用 `shrink_reload(mode="hot")` 重载石英核心，`mode="cold"` 通过 AstrBot 原生接口重启整个进程（会短暂断开平台连接）。独立执行器持久记录请求，等待调用中的后台任务退出；有其他执行中的任务时拒绝。提交只代表待处理，新核心启动代次改变且健康检查通过才记成功，结果经统一表达链路回传。重载回执未知时不自动再次重启。重载不会合并或部署草稿，代码部署仍须使用工作台测试与部署流程。
